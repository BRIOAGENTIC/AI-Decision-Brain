The pipeline

Three steps, no manual triage

Each ticket moves through the same short path, whether it's a client invoice or a system that's gone quiet.

01

Monitor

Your monitoring tool notices something's off — an invoice past due, a sync job gone silent.

02

Judge

03

Act

n8n — or any automation tool — reads the verdict and fires the right response. No one had to triage it by hand.

API reference

Wire it into automation

One endpoint, one decision. Point any HTTP-capable tool at it — n8n, Zapier, a cron job — and branch on what comes back.

Request — POST /judge

{ "type": "invoice", "client": { "name": "Northwind Creative", "tier": "priority", "systems_used": "Slack, QuickBooks", "escalation_contact": "ops-lead@agency.com" }, "item": { "amount": 4200, "days_overdue": 45 } }

Response

{ "severity": "high", "action": "escalate", "message": "45 days overdue on a priority account — loop in the escalation contact." }
Header required: every call to /judge needs x-api-key set to your API_SECRET. GET /health is open, for uptime checks.
In n8n: an HTTP Request node calls /judge with the ticket, a Switch node branches on severity or action, and Slack / Gmail / whatever node fires from there.
Decision Brain — built on Gemini a triage layer, not a replacement for judgment
